# Mind for VS Code

日本語プログラミング言語 [Mind](https://www.scripts-lab.co.jp/mind/whatsmind.html)（Scripts Lab Inc.）を VS Code で編集するための拡張機能です。**VS Code 1.91.0 以上**で動作します。構文ハイライトや診断などの標準機能は Mind の配布物や Docker なしで使えます。

## はじめに

1. `.src` または `.mnd` ファイルがあるフォルダーを VS Code で開きます。
2. ワークスペースの設定で、`mind.distribution` を使っている配布物に合わせます。
3. コマンドパレットで **`Mind: このワークスペースの文字コードと関連付けを設定する`** を実行し、ソースの文字コードを選びます。

| `mind.distribution` | 配布物 | コマンドで最初に提示する文字コード | 標準単語辞書の出典 |
|---|---|---|---|
| `windows-9`（既定） | Mind 9 for Windows | Shift_JIS | 9.05（大域 1,241 語） |
| `linux-8` | Mind 8 for Linux | EUC-JP | 8.0.08（大域 1,226 語） |

コマンドは選んだ文字コードを Mind 言語の `files.encoding` に設定し、`*.src` を Mind に関連付けます。変換ラッパーを使う構成では UTF-8 を選べます。ステータスバーの言語モードが **Mind** になっていることを確認してください。

## エディター機能

| 機能 | 内容 |
|---|---|
| ハイライト | 構文ハイライトと Semantic Tokens で、キーワード、ユーザー定義の単語、標準単語などを区別します。 |
| アウトライン | 定義の下に局所変数と局所処理単語が表示されます。 |
| 定義への移動・参照の検索 | `反応し` で **F12** を押すと `反応する` の定義へ移動し、**Shift+F12** で参照を検索できます。対象は編集中のファイルです。 |
| 補完 | 局所変数、このファイルの定義、制御構文、スニペット、標準単語の順で候補を表示します。 |
| ホバー | 単語の種別、スタック仕様、属性を表示します。標準単語では辞書の出典も表示します。 |
| リネーム | **F2** で編集中のファイルにある定義と呼び出しを更新します。 |
| 診断 | 構文の対応ミス、未定義単語、定義より前での参照、否定形、空白が不足した括弧コメントを指摘します。 |
| 字下げ | `ならば` や `つぎに` などの構文に合わせて入力時の字下げを調整します。 |

### 処理単語のリネーム

0.1.5 では、呼び出しの活用形を新しい名前に合わせます。`かごに入れる` を `買う` に変えると、呼び出しの `かごに入れ` は `買い` になります。`カートに追加` に変えた場合、呼び出しも `カートに追加` になります。

### 単語の照合と表記

- 照合時に送り仮名を落とすため、`繰り返す`、`繰り返し`、`繰返し` は同じ単語として扱います。
- Mind 8 for Linux（`linux-8`）では `カウント` と `ｶｳﾝﾄ` は別の単語です。半角中点 `･` の有無も区別します。Mind 9 for Windows（`windows-9`）では半角カナを全角カナと同じものとして扱います。
- 単語の区切りはタブ、半角・全角の空白、半角・全角のカンマ、読点です。`赤い色で表示する` は 1 単語です。
- `（ ）` の直前と直後がそれぞれ区切り文字か行の端に当たる場合、括弧内はコメントになります。単語に続けて書いた `（ ）` は配列の添字として使えます。
- トップレベルの `終り。` 以降はコンパイル対象外の範囲として表示します。

## 複数ファイルの診断

未定義単語の診断では、`"x.src"を　コンパイル。` でつながるファイルの大域単語をまとめて照合します。取り込まれる側のファイルを編集中でも、取り込む側の定義を照合に使います。対象はワークスペースのルート内に実体があるファイルです。

VS Code で編集中の文書は、VS Code が選択した文字コードで読み込んだテキストを解析します。複数ファイルの診断でディスクから読み込むソースは UTF-8 として扱います。文字コードを設定するコマンドは、VS Code の読み書きに使う設定を変更します。

取り込み先が見つからない場合（ワークスペース外への参照を含みます）、`mind.library` が `file` 以外の場合、または取り込み関係も `メイン` もないライブラリ断片の場合、未定義単語の診断は省略します。

## 実コンパイラで検査する（任意）

`mind.compiler.enabled` を `true` にすると、保存時に Docker 上の実 Mind コンパイラでも検査します。拡張機能の静的解析に加えて、コンパイラが検出した型や助詞などの問題を確認できます。

Docker を起動し、Mind-Docker の `vendor/` に Mind 8 for Linux の配布物を配置します。Mind-Docker のルートで `make build` を実行すると `mind-docker:8.0.08` ができます。[Mind-Docker のセットアップ手順](https://github.com/shin3tky/Mind-Docker#必要なもの)を参照してください。

実コンパイラを呼び出す際、ワークスペースは読み取り専用でマウントされ、変換や生成はコンテナ内で行われます。Mind 9 for Windows 固有の単語は Mind 8 for Linux のコンパイラではエラーになることがあります。

## 設定

| 設定 | 既定値 | 内容 |
|---|---|---|
| `mind.distribution` | `windows-9` | 標準単語辞書、単語の照合規則、文字コード設定コマンドで最初に提示する文字コードを切り替えます。 |
| `mind.library` | `file` | 使用する標準ライブラリを指定します。GUI 編では `guilib` を指定します。 |
| `mind.diagnostics.undefinedWords` | `true` | 定義されていない単語を指摘します。 |
| `mind.diagnostics.forwardReferences` | `true` | 定義より前の参照を指摘します。 |
| `mind.diagnostics.negativeForms` | `true` | 否定形の送り仮名を指摘します。`表示しない` のように「ない」「ず」で終わる否定はエラー、`表示しないこと` のように否定の意味だけが落ちる書き方は警告です。 |
| `mind.diagnostics.commentParens` | `true` | 空白の不足でコメントとして扱われない `（ ）` を指摘します。 |
| `mind.compiler.enabled` | `false` | 保存時に Docker 上の実コンパイラで検査するかを指定します。 |
| `mind.compiler.docker.image` | `mind-docker:8.0.08` | 実コンパイラでの検査に使う Docker イメージを指定します。 |
| `mind.trace.server` | `off` | Language Server との通信の出力レベルを `off`、`messages`、`verbose` から選びます。 |

## 既知の制限

- 同梱辞書は標準ライブラリ `file` を対象としています。`guilib` を指定した場合は、未定義単語の診断を省略します。
- 字下げの調整は入力時の自動インデントに限ります。
- `条件コンパイル` の配下にある取り込みは、条件にかかわらず複数ファイルの診断に含めます。
